# System Placement Rules

Rules for assigning bodies to orbit slots when rendering a star system in 3D.
Orbit slots are defined in `orbits.json` (ids 0–20, fixed AU distances).
Habitable zone lookups use `STAR_HZ` in `src/lib/orbitData.ts`.

---

## What We Can Derive from World Data

| Field | Derives |
|---|---|
| `stellar[]` | Number of stars, each star's spectral class, system type |
| `STAR_HZ` lookup | Primary star's habitable zone orbit id |
| `uwp.size` | Main world diameter; size 0 = asteroid belt |
| `uwp.atmosphere` | Atmosphere type for rendering |
| `uwp.hydrographics` | Surface type for rendering |
| `remarks` | Trade codes — refine surface palette |
| `pbg.gasGiants` | Count of gas giants in the system |
| `pbg.belts` | Count of asteroid belts in the system |
| `worldsInSystem` | Total body count; subtract main world + gas giants + belts = other rocky worlds |
| `bases` | Naval / Scout / Way station infrastructure |

---

## System Types

Derived from the number of entries in `stellar[]`.

| Type | stellar[] count | Layout |
|---|---|---|
| Solitary | 1 | Primary only |
| Binary | 2 | Primary + far secondary |
| Trinary | 3 | Primary + close dwarf companion + far secondary |

---

## Star Placement Rules

### Solitary
- Index 0 → primary, at center, no orbitId

### Binary
- Index 0 → primary, at center
- Index 1 → far companion, role: `"far-companion"`, proximity: `"far"`, high orbitId (orbit 16+)

### Trinary
- Index 0 → primary, at center
- Index 1 → close dwarf companion, role: `"close-companion"`, proximity: `"close"`, orbitId 0 (0.2 AU) by convention
- Index 2 → far secondary, role: `"far-companion"`, proximity: `"far"`, high orbitId (orbit 16+)

The close companion and primary form a combined gravitational center for the inner system.

**Companion orbital separation** — exact orbitId for close/far companions requires T5 Book 3 generation rules or canonical data. Until then:
- Close companion → orbitId 0 (convention)
- Far companion → canonical AU if known (e.g. Regina M3 V = 5000 AU → orbitId 16)

---

## Main World Placement

The main world always has a direct relationship with the primary — either it orbits the primary directly, or its parent body does.

### Case 1 — Direct orbit
Main world sits in `orbits[]` at the habitable zone orbit id (from `STAR_HZ`).

```
orbitId = round(STAR_HZ[spectral].hz)
```

### Case 2 — Satellite
Main world is a moon of a parent body. The parent body occupies the HZ orbit slot in `orbits[]`. The main world appears in the parent's `moons[]` with `isMainWorld: true`.

- If `pbg.gasGiants > 0` → parent is a gas giant
- If `pbg.gasGiants === 0` → parent is a rocky body with `isParent: true`

Maximum one level of nesting. The parent always sits in a direct orbit of the primary.

### Case 3 — Asteroid belt
When `uwp.size === 0` the main world is a belt. The belt occupies the HZ orbit slot directly in `orbits[]` with `isMainWorld: true`. No parent body needed.

## T5 Book 3 Chart P1 — Placement Sequence

Bodies are placed in this order:

### 1. Main World
- If satellite + GG present → place GG at HZ orbit, main world in GG's `moons[]`
- If satellite + no GG → place Bigworld at HZ orbit (`isParent: true`), main world in Bigworld's `moons[]`
- If asteroid belt (`uwp.size === 0`) → place belt at its orbit **without regard to HZ**
- Otherwise → place world directly at HZ orbit

### 2. Gas Giants
Rotate placement between primary and far companion only.
Close companion is excluded — no bodies orbit the close companion independently.

- Body 1 → primary system
- Body 2 → far companion system
- Body 3 → primary system
- … and so on

### 3. Planetoid Belts
Same rotation rule — alternate between primary and far companion only.

### 4. Other Worlds
Same rotation rule — alternate between primary and far companion only.
Orbit slot determined by T5 Book 3 p2 table (`p2.json`):
- Use the **World1** column for all worlds except the last
- Use the **World2** column for the last world placed
- World1 and World2 values are **absolute orbit ids** (not relative to HZ)

---

## p2 Table — How to Read It

Roll 2D6 (modified by DMs — result can be as low as 1).

| Column | Relative to HZ? | Used for |
|---|---|---|
| LGG | Yes — add to HZ orbitId | Large gas giant placement |
| SGG | Yes — add to HZ orbitId | Small gas giant placement |
| IG | Yes — add to HZ orbitId | Ice giant placement |
| Belt | Yes — add to HZ orbitId | Planetoid belt placement |
| World1 | No — absolute orbitId | All other worlds except the last |
| World2 | No — absolute orbitId | The last other world placed |

**Negative GG/Belt results** mean the body would land inside or very near the star. Adjust to the nearest valid orbit (rule from p2 notes).

**Duplicate orbits** — if two bodies land on the same orbitId, adjust one to the nearest available adjacent orbit.

Roll 2D6 per gas giant to determine size and type.

| Roll | SizeCode | Diameter (miles) | Type | Gravity |
|---|---|---|---|---|
| 1 | L | 20,000 | SGG | 0.2 |
| 2 | M | 30,000 | SGG | 0.3 |
| 3 | N | 40,000 | SGG | 0.4 |
| 4 | P | 50,000 | SGG | 0.5 |
| 5 | Q | 60,000 | LGG | 0.6 |
| 6 | R | 70,000 | LGG | 0.7 |
| 7 | S | 80,000 | LGG | 0.8 |
| 8 | T | 90,000 | LGG | 0.9 |
| 9 | U | 125,000 | LGG | 1.2 |
| 10 | V | 180,000 | LGG | 1.8 |
| 11 | W | 220,000 | LGG | 2.2 |
| 12 | X | 250,000 | LGG | 2.5 |
| 13+ | Y | 250,000 | >LGG | 3.0 |

**Converting SGG to IG:** After rolling all gas giants, convert every 2nd SGG in sequence to an Ice Giant (IG). Same size code, diameter, and gravity — only the type changes. This determines which p2 column is used for orbit placement.

**Brown dwarfs** are always size Y (250,000 miles diameter).

**Diameters are in miles.**

## Orbital Animation and Time

**Epoch** — Imperial year 1000, day 1. All orbital starting angles are calculated from this fixed point.

**Game start** — Imperial year 1106, day 1. Elapsed days from epoch at game start = (1106 - 1000) × 365 = 38,690 days.

**Position at any Imperial date:**
```
elapsedDays = (imperialYear - 1000) * 365 + imperialDay
periodDays  = AU^1.5 * 365   (for primary star; adjust by stellarMass for other star types)
angle       = (360 / periodDays) * elapsedDays   (degrees, mod 360)
```

Orbital periods are never stored — derived at render time from `au` + stellar mass.
Stellar mass is derived at render time from spectral class via a `STELLAR_MASS` lookup table (same pattern as `STAR_HZ` in `orbitData.ts`).

**Two rendering modes:**
- **Distant system** — animated. Bodies move along their orbits using elapsed game time.
- **Current system** — static snapshot. Bodies positioned at current Imperial date but do not animate at celestial scale.
